    벤치마크 실행¶

    GUAM과 baseline을 동일 조건에서 비교하는 절차. 저장소에 포함된 하니스 (scripts/benchmarks/)의 사용법.

    왜 하니스를 쓰는가¶

    AutoML 비교에서 수치가 어긋나는 원인은 대개 모델이 아니라 측정 조건. 하니스는 다음을 강제하여 그 변수를 제거.

    • 모든 시스템에 동일한 fold 분할·seed·timeout 적용
    • 주 메트릭의 task별 고정 — binary=AUC, multiclass=log-loss, reg=RMSE
    • GPU 실패 시 CPU 무음 폴백 금지. 무효(status != "ok")로 기록해 리포트에 노출
    • 상수·NaN 등 퇴화 예측의 무효 처리(낮은 점수가 아니라 측정 실패로 취급)
    • 실행 구성(config)과 전송 회계(device 메모리·D2H 횟수)를 결과에 동봉

    1. 설치¶

    uv sync --extra gpu --extra dev --extra benchmark

    [benchmark] 는 채점·데이터 취득용 호스트 의존성(scikit-learn·scipy·openml)을 추가. GUAM 본체와 무관하며 하니스에서만 사용.

    2. 단일 실행¶

    python -m scripts.benchmarks.run_benchmark \
  --system guam --dataset california --timeout 600

    출력은 experiments/log.md 형식의 한 행.

    | 0 | 2026-09-01 | guam x california [completion f0] | 0.8123 | 0.8090 | - | 2048 | 57 | 0 | - |

    --append 지정 시 experiments/log.md 에 직접 추가.

    사용 가능한 데이터셋¶

    이름 task 출처 비고
    adult binary OpenML 1590 중규모 parity
    pendigits multiclass OpenML 32 소규모(11k), 빠른 확인용
    covertype multiclass OpenML 1596 대규모(581k)
    california reg sklearn 네트워크 불필요
    higgs binary OpenML 23512 대형 실데이터(옵션)
    scaling_clf_1m binary 합성 1M×50 GPU 이득 측정용

    레지스트리에 없는 OpenML 데이터는 인라인 표기로 직접 지정.

    --dataset "openml:1461:binary"

    3. baseline과 비교¶

    --system 만 바꿔 동일 조건으로 반복.

    for sys in guam lightautoml autogluon xgb; do
  python -m scripts.benchmarks.run_benchmark \
    --system "$sys" --dataset adult --timeout 600 --json-out "bench_${sys}.json"
done

    AMLB 규정 baseline 3종(constant·rf·tuned_rf)은 집계의 기준점. GPU 없이도 실행 가능하므로 하니스 동작 확인에 적합.

    python -m scripts.benchmarks.run_benchmark --system constant --dataset california --timeout 60

    | 0 | 2026-09-01 | constant x california [completion f0] | 1.1866 | 1.1852 | - | - | - | 0 | - |

    4. 다중 fold와 구조화 레코드¶

    소규모 데이터셋의 노이즈 대응에는 다중 fold 반복이 필요.

    python -m scripts.benchmarks.run_benchmark \
  --system guam --dataset adult --timeout 600 \
  --folds 0,1,2,3,4 --json-out bench_guam_adult.json

    --json-out 레코드에는 fold별 원점수(fold_score), 실행 구성(config), 실제 학습된 알고리즘(fitted_algos), 예산 회계(budget), device 메모리·전송 회계가 포함. 표 재생성의 근거 자료.

    5. 실험 모드¶

    모드 의미 용도
    --mode completion 동일 구성을 완주시키고 소요 시간 측정. timeout은 안전 상한 RQ1 parity
    --mode budget timeout이 시간 예산. 소비율(budget_utilization) 기록 RQ2 속도·예산

    budget 모드에서는 예산을 소비하지 않는 결정적 시스템의 특성이 수치로 노출.

    6. GPU 없는 환경의 동작¶

    GUAM 러너는 GPU가 없으면 CPU로 폴백하지 않고 무효로 기록.

    | 0 | 2026-09-01 | guam x california [completion f0] [INVALID crashed: no GPU available (RAPIDS required)] | - | ...

    CPU로 대체한 숫자가 GPU 결과인 것처럼 표에 오르는 사태를 막기 위한 설계. GPU 미가용을 즉시 오류로 드러내려면 러너 생성 시 require_gpu=True 지정.

    7. 구성 A/B 비교¶

    GUAM 내부 구성을 바꿔가며 측정할 때는 실행 축과 라벨을 함께 지정.

    python -m scripts.benchmarks.run_benchmark --system guam --dataset adult \
  --use-algos xgb --config-label A --json-out a.json

python -m scripts.benchmarks.run_benchmark --system guam --dataset adult \
  --use-algos nn,xgb --blender nelder_mead --config-label B --json-out b.json

    미지정 플래그는 러너에 전달되지 않으므로, 무플래그 실행은 프리셋 기본 구성과 동일.
