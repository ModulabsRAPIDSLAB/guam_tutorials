    멀티-GPU¶

    GUAM의 단일 GPU·분산 실행 선택 방식과 현재 분산 실행 범위.

    알파

    백엔드 선택과 클러스터 수명주기는 안정. TabularAutoML 을 통한 end-to-end 분산 학습은 현재 한 가지 구성만 지원 — end-to-end 지원 범위 참조. 범위 밖 구성은 조용히 축소하지 않고 명시적 오류로 거절.

    설치¶

    uv sync --extra gpu --extra dist --extra dev

    [dist] 는 Dask-CUDA·Dask Distributed·Ray 추가. cuDF·cuML은 포함하지 않으므로 [gpu] 와 함께 설치.

    백엔드 선택¶

    compute 동작
    "auto" (기본값) GPU 2장 이상과 [dist] 런타임 감지 시 Dask, 그 외 단일 GPU
    "single" 항상 프로세스 내 단일 GPU 경로 — 기본 프리셋 전체
    "dask" 항상 Dask. 런타임·GPU 부족 시 실패하며 단일 GPU로 폴백하지 않음

    GPU가 전혀 없으면 CPU 실행 대신 ImportError.

    from guam.automl.presets import TabularAutoML

auto = TabularAutoML(task="binary", compute="auto")
single = TabularAutoML(task="binary", compute="single", gpu_ids="0")
managed = TabularAutoML(task="binary", compute="dask", n_gpus=2)

    관리형 클러스터 또는 기존 Client¶

    n_gpus(또는 gpu_ids) 지정 시 GUAM이 LocalCUDACluster 를 생성하고 close() 에서 정리. 운영 중인 클러스터를 재사용하려면 해당 Client를 전달. GUAM은 자신이 만들지 않은 Client를 닫지 않으며, worker topology의 정본이 Client이므로 dask_client 와 n_gpus·gpu_ids 동시 지정 불가.

    from dask.distributed import Client

client = Client("tcp://scheduler:8786")
automl = TabularAutoML(task="reg", compute="dask", dask_client=client)

    작업 종료 후 automl.close() 호출. GUAM이 생성한 자원만 해제.

    end-to-end 지원 범위¶

    TabularAutoML 을 통한 Dask 경로의 현재 지원 범위:

    • 수치형 회귀(task="reg")
    • XGBoost 단일 모델 — use_algos=["xgb"]
    • K-fold 검증
    • 피처 파이프라인 없음 — features="none" — 및 HPO 없음

    입력은 Dask-cuDF frame 또는 Dask reader가 지원하는 파일 경로. 결과는 lazy DaskCudfDataset. CUDA 데이터 생성 전에 클러스터를 먼저 시작해야 하므로 예시는 파일 입력 사용.

    automl = TabularAutoML(
    task="reg", compute="dask", n_gpus=2,
    general_params={"use_algos": ["xgb"], "features": "none", "n_folds": 2},
)
try:
    oof = automl.fit_predict("train.parquet", roles={"target": "target"})
    pred = automl.predict("test.parquet")
finally:
    automl.close()

    분류·앙상블·HPO·holdout·walk-forward·refit은 Dask 경로에서 거절. compute="auto" 가 Dask를 선택한 경우에도 같은 제한이 적용되므로, 멀티-GPU 장비에서 기본 프리셋 전체를 쓰려면 compute="single" 지정.

    백엔드별 구현 현황¶

    분산 구현은 프리셋 아래 계층에 존재. DaskCudfDataset 과 DaskTrainValidIterator 를 직접 전달하면 사용 가능하며, TabularAutoML 연결은 단계적으로 진행 중.

    구성요소 분산 방식 TabularAutoML 경유
    XGBoost xgboost.dask 지원 (위 구성 한정)
    LightGBM lightgbm.dask 미연결
    RandomForest·Linear (cuML) cuml.dask 미연결
    CatBoost 단일 프로세스 내 CatBoost 자체 멀티 디바이스 학습, gpu_ids 로 장치 지정 단일 프로세스 경로
    Dask-GPU 경로가 없는 모델 RayBackend 미연결
    스케줄링 GPU 자원 annotation·worker 검증 Dask 백엔드가 사용

    미완료: 분산 OOF 예측 위 블렌딩, 멀티-GPU 스케일링 벤치마크.

    문제 해결¶

    • ImportError: Numba needs NumPy 2.0 or less — numpy 업그레이드 발생. RAPIDS 26.2는 numpy<2.1 필요. lockfile로 재설치하거나 새 환경에서 시작.
    • ValueError: unsupported general_params for Dask preset — 위 지원 범위 밖 구성. compute="single" 사용 또는 구성 축소.
    • 일부 GPU만 사용됨 — CUDA_VISIBLE_DEVICES 확인. GUAM은 부모 프로세스의 가시성 마스크 안에서 gpu_ids 를 해석.
