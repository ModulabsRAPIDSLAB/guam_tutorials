    Multi-GPU¶

    How GUAM chooses between single-GPU and distributed execution, and what runs distributed today.

    Alpha

    Backend selection and cluster lifecycle are stable. End-to-end distributed training through TabularAutoML currently covers one configuration — see What runs end to end. Everything outside it is rejected with an explicit error rather than silently degraded.

    Install¶

    uv sync --extra gpu --extra dist --extra dev

    [dist] adds Dask-CUDA, Dask Distributed and Ray. It does not install cuDF or cuML; pair it with [gpu].

    Choosing the backend¶

    compute Behaviour
    "auto" (default) Dask when two or more GPUs and the [dist] runtime are detected, single GPU otherwise
    "single" Always the in-process single-GPU path — the full default preset
    "dask" Always Dask. Fails if the runtime or GPUs are missing; never falls back to single

    With no GPU at all, GUAM raises ImportError instead of running on CPU.

    from guam.automl.presets import TabularAutoML

auto = TabularAutoML(task="binary", compute="auto")
single = TabularAutoML(task="binary", compute="single", gpu_ids="0")
managed = TabularAutoML(task="binary", compute="dask", n_gpus=2)

    Managed cluster or your own client¶

    With n_gpus (or gpu_ids), GUAM starts a LocalCUDACluster and tears it down in close(). To reuse a running cluster, pass its client instead. GUAM never closes a client it did not create, and the client's worker topology is authoritative, so n_gpus and gpu_ids cannot be combined with dask_client.

    from dask.distributed import Client

client = Client("tcp://scheduler:8786")
automl = TabularAutoML(task="reg", compute="dask", dask_client=client)

    Call automl.close() when you are done; it releases only what GUAM created.

    What runs end to end¶

    Through TabularAutoML, the Dask path currently supports:

    • numeric regression (task="reg")
    • a single XGBoost model — use_algos=["xgb"]
    • K-fold validation
    • no feature pipeline — features="none" — and no HPO

    Input is a Dask-cuDF frame or a file path the Dask reader supports. Results come back as a lazy DaskCudfDataset. Start the cluster before creating CUDA data, which is why the example reads from files.

    automl = TabularAutoML(
    task="reg", compute="dask", n_gpus=2,
    general_params={"use_algos": ["xgb"], "features": "none", "n_folds": 2},
)
try:
    oof = automl.fit_predict("train.parquet", roles={"target": "target"})
    pred = automl.predict("test.parquet")
finally:
    automl.close()

    Classification, ensembles, HPO, holdout, walk-forward and refit are rejected on the Dask path. These limits also apply when compute="auto" picks Dask, so on a multi-GPU machine use compute="single" to run the full default preset.

    Backend coverage¶

    Distributed implementations exist below the preset. They are used directly when you pass a DaskCudfDataset and a DaskTrainValidIterator, and are wired into TabularAutoML step by step.

    Component Distributed mechanism Through TabularAutoML
    XGBoost xgboost.dask yes, in the configuration above
    LightGBM lightgbm.dask not yet
    RandomForest, Linear (cuML) cuml.dask not yet
    CatBoost CatBoost's own multi-device training in one process, fed from gpu_ids single-process path
    Models without a Dask-GPU path RayBackend not yet
    Scheduling GPU resource annotations and worker validation used by the Dask backend

    Still open: blending over distributed out-of-fold predictions, and the multi-GPU scaling benchmark.

    Troubleshooting¶

    • ImportError: Numba needs NumPy 2.0 or less — something upgraded numpy. RAPIDS 26.2 needs numpy<2.1; reinstall with the lockfile or start from a fresh environment.
    • ValueError: unsupported general_params for Dask preset — the configuration is outside the supported set above. Use compute="single" or reduce the configuration.
    • GPUs not all used — check CUDA_VISIBLE_DEVICES. GUAM maps gpu_ids inside the parent process's visibility mask.
