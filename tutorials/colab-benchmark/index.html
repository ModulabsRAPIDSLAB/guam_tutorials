    Benchmarking on Colab¶

    A ready-to-run Colab notebook that installs GUAM, runs the benchmark harness on OpenML datasets and prints a summary table. Edit one cell, then Run all.

    Open in Colab Download .ipynb

    Status

    The notebook has been executed end to end outside Colab (CPU baseline plus a GUAM run correctly recorded as invalid without a GPU). A full Colab T4 run has not been recorded yet. The team's proven GPU environment is Kaggle T4, which the notebook's install approach is copied from.

    Before you run¶

    1. GPU runtime. Runtime → Change runtime type → T4 GPU.
    2. Access token. The GUAM repository is private, so the notebook clones it with a token. Open 🔑 Secrets in the left sidebar, add GH_TOKEN with a fine-grained GitHub token that has read access to ModulabsRAPIDSLAB/GUAM, and turn on notebook access. Without the secret the notebook asks for the token once. The token is removed from the clone's remote URL and from any error output.

    Configure¶

    Everything you normally change is in the first code cell.

    Setting Default Meaning
    DATASETS ["adult", "pendigits", "california"] registry names, or "openml:<id>:<task>"
    SYSTEMS ["guam", "constant"] systems to run; constant, rf, tuned_rf are the AMLB reference baselines
    FOLDS [0, 1, 2] holdout folds; each fold is one measurement
    TIMEOUT 600 seconds per run
    MODE "completion" completion for parity, budget when the timeout is a time budget
    MAX_ROWS None stratified subsample cap for very large datasets
    CONFIG_LABEL "colab" tag written into every record; change it between A/B batches
    GUAM_REF "main" branch or tag to benchmark
    REQUIRE_GPU True stop at the environment check instead of recording invalid GUAM runs

    xgb, lightautoml, autogluon and h2o can be added to SYSTEMS; the notebook installs them only when selected.

    How it installs, and why¶

    The notebook does not run pip install guam[gpu]. A dependency-resolving install can upgrade numpy past 2.0, and RAPIDS 26.2 depends on a numba that then refuses to import — taking cuDF with it. Instead the notebook:

    • checks that a GPU is visible, that cuDF and CuPy import, and that numpy is below 2.1
    • imports GUAM from a source checkout through PYTHONPATH, using the RAPIDS stack already in the image
    • installs only missing lightweight packages (omegaconf, optuna, scikit-learn, scipy, openml) with the current numpy and pandas versions pinned

    This is the same approach behind the team's Kaggle T4 suite runs.

    Reading the output¶

    Each run is one child process of python -m benchmarks.run_benchmark, so one failure does not stop the batch. Runs that already finished successfully are skipped if you run the cell again.

    The summary groups runs by dataset and system:

    Column Meaning
    runs / ok runs attempted / runs with status == "ok"
    score_mean / score_std main metric over folds — AUC is higher-is-better, log-loss and RMSE lower-is-better
    train_s fit plus predict time
    gpu_mb measured peak device memory

    Invalid runs are listed below the table with their reason. A GUAM run is never replaced by a CPU result; without a GPU it is recorded as invalid.

    Results¶

    The last cell zips everything under guam_bench_results/ and downloads it:

    • records/ — one JSON record per system × dataset × fold, the raw evidence
    • summary.csv, summary.md — the table above

    For the full statistical report (paired tests, confidence intervals, failure policies), point the aggregator at the records from a GUAM checkout:

    PYTHONPATH=.:scripts python -m benchmarks.aggregate --results guam_bench_results/records \
  --treatment guam --baselines constant
